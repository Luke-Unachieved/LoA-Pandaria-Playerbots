# One autonomous native player: reuse and remaining gaps

Source-only status. No native compilation, linking or gameplay proof is claimed. Paths are relative to the uploaded `modules/mod_playerbots/src`. The designated actor is one existing bot; other actors retain existing behavior. The intended actor plays normally, with diagnostics secondary.

| Capability | Native implementation retained | V19 work / remaining gap |
|---|---|---|
| Persistent native session | CharacterCache account identity, native random-account allowlist, `PlayerbotHolder::QueuePlayerBot` / world callback / GUID lease | Exact existing actor logs in/relogs with bounded backoff after world startup; conflicting sessions, raid ownership, reset/service rows and shutdown refuse admission. No character creation or live operation performed here. |
| Background activity without humans nearby | Exact current composed V18 `AllowActive` / `AllowActivity` | Only the verified V19 actor bypasses random rotation and detailed-movement throttling, after native invalid-state guards. Existing native LFG/instance/combat activity rules already cover V18 admitted dungeon bots. No global population activity change. |
| Activity selection | `NewRpgStatusUpdateAction::Execute`, `RandomChangeStatus`, `CheckRpgStatusAvailable` | Native weighted statuses choose quest/grind/wander/camp/rest/flight/PvP. They are not a complete needs planner. |
| Quest progression | `NewRpgBaseAction` quest-giver/accept/reward/POI, `NewRpgDoQuestAction`, native eligibility/chain checks | Real quest/objective state and reward flags observed. Known-broken templates rejected instead of auto-completed. Scripted objectives and special/group quests remain incomplete coverage. Attempt counters are never success evidence. |
| Combat / loot | Existing class engines, `AttackActions`, `LootAction`, grind and quest strategies | No new targeting or combat executor; no forced combat clear. |
| Earned gear / bags | `EquipUpgradesPacketAction`, ItemUsage, owned-item equip and bag comparison | Factory creation and automatic level-up generated gear are excluded. Goal-driven bag acquisition needs further integration. |
| Repair / sell / supplies | MaintenanceValues, BudgetValues, native `RepairAllAction`, `SellAction`, `BuyAction`, TravelTarget and MoveToTravelTargetAction | Live-need service routing on the current map now selects a bounded nearby catalog, then uses native NPC/cost checks on arrival. Cross-map planning and runtime proof remain absent. |
| Training / professions | Native `TrainerAction::Iterate/Learn`, `RpgTrainAction`, owned money and real trainers | No generated skill levels/recipes. Profession choice and complete independent progression remain gaps. |
| Gathering | `GatherAction` nearby node/skill checks and native loot | Opportunistic gathering exists; recipe-driven node routing not implemented. |
| Crafting | `CraftRandomItemAction` and native casting with known spells/materials | Bridge narrows actor craft selection to useful/skill-up recipes and one native cast, with actor-only priority fixes. Full material/recipe goal planner remains absent. |
| Trade | `RpgTradeUsefulAction`, native trade packet/action handling | Bot useful-item transfer reusable. No market/economy planner; action result is not completed trade proof. |
| Dungeons | LFG roles/proposals/acceptance/normal entry and existing instance strategies | Native join consumes human-demand snapshot. Independent needs-based dungeon selection is not implemented. V18 training roster excludes this actor. |
| Battlegrounds | Native BG join/status and per-map tactics | Existing demand/config controls retained. No level bypass or forced combat clear for actor. Independent BG preference and unreachable healer walking remain gaps. |
| Death | Normal release, corpse walking/reclaim, resurrection handlers | Offscreen corpse teleports, raw spirit-healer resurrection and repop relocation excluded. Native paid spirit-healer interaction still needs implementation. |
| Stuck recovery | Existing MoveFarTo primary/cone paths; existing owned hearthstone `use` action | Only after real failed alternatives/time budget; native legal/cooldown checks; cast+bind arrival observations; no raw recovery teleport. Graph portal shortcuts excluded until actual object/spell activation exists. |
| XP policy | Existing per-player native kill/quest/explore `getRate(..., player)` | Observe AI 1x mismatch, never rewrite rates. Human 5x policy unchanged/unverified here. `Player.cpp` gathering uses global `RATE_XP_GATHER`; complete AI/human gather policy needs actual core rate source/runtime validation. |

`AiFactory` currently chooses `new rpg` OR `rpg`, and stock `RpgStrategy` omits several registered service nodes. The separate need bridge composes existing service triggers with NewRpg, rather than writing a second gameplay executor. It does not make every row complete.

The mutation guard inventory includes actual `Factory/BotFactory.cpp` (the fork's class name), random managers/level resets/login starter completions, AutoMaintenanceOnLevelup, quest fabricated-completion/sync fallback, dynamic population relocation, NewRpg stuck/transport graph shortcuts, death relocation, BG placement/Tol Barad/arena fallback, Lost City rescue, free taxi money, and guild emblem top-up. Normal taxi cross-map transfer and ordinary native spell/core invitation transitions are retained. Scenario/GM external intervention is outside the autonomous scope; do not assign this actor to scenario control.

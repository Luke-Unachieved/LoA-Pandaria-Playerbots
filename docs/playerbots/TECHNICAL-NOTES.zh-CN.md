# Playerbots 技术阅读备忘与团队 AI 协作边界

日期：2026-11-18。文档性质：工程阅读备忘，不是上游功能保证、全技能测试认证或发布说明。

## 证据范围

本文汇总此前开发工作中的静态源码阅读与局部运行观察。本次整理没有重新逐文件审读远端分支；行号、行为和实验值可能对应不同开发快照，后续修改必须先对照实际 commit、编译 TU 和运行二进制。标记 R 为既有阅读报告，H 为待验证静态风险，运行观察只适用于其当时条件。

此前本地模块的 .cpp/.h 阅读审计口径为 1338 个唯一文件：原记录587，附加记录751，交集0、缺失0、额外0；之前 Formations.cpp/.h 重复计数已扣除2。附加751项尚未合并回原账本，本公开备忘没有逐路径清单，因此不构成可独立复算的源码覆盖清单，也不是对当前远端树的覆盖认证。

团队 AI 应与原生 Playerbots 互补：保留原生职业执行能力，学习团队目标、职责、机制和时机；不把固定路线、攻略 if/else 或重新实现原职业循环称为训练成果。实时验收应测事件到实际执行的完整延时，不能只报告模型推理耗时。

# 架构与职业链

## 原生执行层

AiFactory 创建职业/专精上下文与战斗、非战斗策略。策略安装 Trigger，触发候选 Action；候选受优先级、Multiplier、前置/替代动作、资源和状态约束，再进入实际执行。Value 不全是纯读缓存，有些取值会修改目标或等待状态；isUseful 也不能默认无副作用。

模型适合决定团队焦点、职责、机制站位与时机，交由原生技能动作实施。不要全局重排全部职业候选去替代原治疗或循环。Multiplier=0 会屏蔽动作，提高 relevance 未必有用。关闭 boost 也不表示已取得全部爆发控制权，因为部分爆发在职业默认触发器。

### 原生集火链

- AiFactory.cpp:648–769：非战斗安装 dps assist，坦克有 tank assist，后续配置仍可能改写。
- DpsAssistStrategy.cpp:5–8：not dps target active → dps assist，优先级 50。
- GenericTriggers.cpp:544–557：dps target 存在且 current 不同；不以自身战斗或 master 为必需条件。
- DpsTargetValue：优先 RTI，否则 attackers；仍受可见性、LOS、合法目标等条件。
- DpsAssistAction → AttackAction::Attack → current/战斗引擎/原生 Attack。
- current 等于 dps target 但 victim=0 不一定永久卡死，原生 melee 仍可能使用 current 恢复。不能只凭一个字段认定故障。

### 防护圣骑士

AiFactory.cpp:395–397 安装 tank/tank assist/pull。TankPaladinStrategy.cpp:81–85 的 3 圣能或 90174 Divine Purpose 触发 Shield of Righteous，优先级 DEFAULT+.6，高于 Crusader+.5、Avenger shield+.45。PaladinActions.h:420 旧键映射实际动作。核心 spell_paladin:352–373 命中后应用/延长 132403 减伤 3 秒与 Bastion，故动作提交不等于减伤已生效。

HP50 触发 Divine Protection，HP20 触发 Ardent Defender；HP70 且 Bastion≥3 有 Eternal Flame。Ardent Defender 核心吸收/致死保护/治疗及内部 120 秒冷却已追到。Avenging Wrath、Guardian Kings 直接在坦克策略，PaladinBoostStrategy 空并不等于无爆发。团队层缺口是伤害窗口预测、外部减伤分配、保留和效果归因。

### 神圣圣骑士

AiFactory.cpp:398–399 安装 heal/dps assist/cure/bcast。危急队友的原生梯队已有 Holy Shock、Eternal Flame、Flash、Divine Light、Holy Light。道标主坦、无敌和群体爆发不是空白。

核心道标转移比例按技能不同（报告：Holy Light100%、部分群疗15%、一般50%），不能因没有直接主坦治疗日志就判未治疗。PaladinHurtGroupTrigger:83–110 找到 10 码受伤簇但只返回布尔，执行时再次选择普通待治疗队友，存在簇中心丢失风险 H。Eternal Flame 动作要求 3 圣能/90174，但核心支持 1–3 与免费施法机制；这是机器人策略保守，不是核心不能施放。

### 奥术法师

### 恢复萨满

已有激流、治疗链、治疗雨、Unleash Elements、多人低血 Ascendance、Earth Shield、回蓝和驱散。核心治疗链首目标有自己的激流时 1.25 倍；候选先后并不保证执行时再次选择的是同一目标。未见 Spirit Link 自动职业联动；Healing Tide 注册了，但报告只在元素/增强低自身血量触发器见自动触发。图腾槽已有 Mana Tide 保护，不能说完全没有覆盖保护。

### 潜行者

Unit::AttackStop 清 victim/unit target/melee flag，但不清 Playerbot current。CombatStop 进一步清战斗。Vanish 1856→18461 在无进行中 encounter 条件下调用 CombatStop，小怪也须看 encounter 状态。Killing Spree 无效目标分支可能 AttackStop。

实际 DBC 1784→SpellMisc380，Attributes 0x1A150010 含 STOP_ATTACK_TARGET 0x00100000；绑定 Spell.cpp:4424–4425 / Unit.cpp:8967–8998。某潜行日志停攻后 14.567 秒恢复，消失 1.692 秒；另一个运行原版恢复 0.786–1.705 秒。不同初始状态不可当作同条件改进对照。

SetBehind 拒绝非近战距离或移动目标；SetFacing 转向并设置 reactDelay，不保证终止 spline，移动切线可能再覆盖朝向。Garrote 不是固定自带 behind/facing 前置，它们可为独立高优先级候选。暂缓移动 spline 中独立 facing 的候选改动没有证明战斗收益，未获晋升。

Expose Armor8647 应用113746，最多3层、每层-4%护甲；原生判断层数/连击点/预计存活时间。反复施放可能是合理叠层，不能只见重复就判兜圈或卡技能。

# 静态风险、协作复用与验证边界

## 不要混淆的结果

Action 返回 true 可能只是等待、转向、打开窗口或提交请求；false 也可能已接任务、转移银行物品、报价、设标记、重置策略。训练奖励和自动重试必须观察真实施法开始、目标、光环、伤害/治疗、死亡、库存变化，不能直接使用返回值。

模型观察不得盲目枚举所有 Value/isUseful：可能有缓存、选目标、预留位置、清目标和等待副作用。聊天命令和同名 Action 不等价，聊天触发器不能天然当可靠事件队列。

## 成长、工具与生命周期

- RandomPlayerbotMgr 的普通 ProcessBot 排除组队/副本/战斗，与另一路 Randomize(false) 条件不同；先看实际配置。战场招募也有排除，不能随意归因。
- BotFactory Randomize(true) 可清战斗、XP、冷却、包、aura、策略并调整装备/宠物，属于生成/测试工具，不是自然成长成果。
- InitBags 删除旧包后旧指针仍非空可能跳过新包 H；不能据此推断所有背包替换故障。
- Scenario/调试工具可传送、复活、清背包、加道具/任务信用、重置首领，必须与原生实战统计分离。
- HireAction 是账号迁移，不是队友递补。leavegroup 可能解散，银行/任务/mail/交易命令有实际写入和非直观返回。
- Travel forced 可能绕过超时，WORK 不等于到达；“reachable”名字不保证做过寻路；getTravelState 可能修改状态。
- TravelNode 需看惰性写入与共享锁、end/size-2 边界；WorldPosition/GuidPosition 必须核对 instance 与 equal_range 空结果。
- 登录/重绑 master、策略 reset、死亡/复活、地图切换都可能改变模型控制假设。目标 GUID 相同不代表生命周期相同。

## 移动与决策验证

原生追随/旅行优先级与手动移动不同。团队 Goal 不应使用足以压过治疗的全局优先级。只暂停自己拥有的路径，凭实际 spline 标识识别；不能清掉他人的移动。清旧 LastMovement 等待只允许有严格所有权与指纹证据的局部操作。

一步移动成功不等于全程队伍协作成功。兜圈应比较对目标的进展、目标变化、移动拥有者、朝向覆盖、路径重发与原生技能执行，不能只看角色原地跑动次数。

纯 idle 调度延时与施法/GCD/reactDelay 等待必须分开记录，降低前者不能误截断后者。按真实事件→采样→推理→入原生队列→选中→施法/移动开始→效果记录端到端延时。报告分位数、最坏值与样本条件，而非只给模型耗时。

## 验收分层

1. 静态调用链与机制证据；
2. 当前真实 TU 编译、统一链接/ABI、部署 EXE 哈希；
3. 原行为回归（职业技能、治疗、移动、真人互动）；
4. 同条件对照，保留失败、中断与不满足条件样本；
5. 团队效果：伤害/治疗、减伤覆盖、机制成功、死亡、通关；
6. 训练闭环：重启可恢复、独立采集训练、留出评估、模型晋升/回退基于效果而非优化器步数。

不把硬编码路由成功、影子建议、编译成功、单次清怪、模型预测准确率称为“团本 AI 完成”。
